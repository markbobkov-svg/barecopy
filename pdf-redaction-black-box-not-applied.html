A black box over text is not a redaction

A rectangle drawn over a paragraph covers it on screen and changes nothing in the file. The words are still there, still selectable, still searchable. This has embarrassed law firms, government departments and newsrooms — the same way every time.

Two things that look identical

Drawing a filled rectangle over text adds a shape to the page. The text underneath is untouched: it remains in the page's content stream, and every PDF reader will happily select it, copy it and search it. The box is paint on glass.

A real redaction is a different operation. It removes the underlying content from the file and then draws the box over the empty space. Only the second one protects anything.

There is a middle case that catches careful people: a redaction mark that was never applied. Acrobat's redaction tool works in two steps — first you mark what should go, then you apply the redactions. Marking looks finished on screen, because the marks render as black boxes. Until you apply them, the text is still in the file.

How to test a PDF in ten seconds

  1. Open the PDF and try to select the text under the black area, then paste it into a text editor.
  2. Use Ctrl+F / Cmd+F to search the document for a word that should be hidden.
  3. If either produces the supposedly hidden text, the file is not redacted — it is covered.

Selecting nothing is not proof on its own: the page may be a scan, or the text may sit under an image. But anything you can select or find is definitive evidence that the content is still in the file.

How to redact properly

In Acrobat: use the Redact tool to mark the content, then choose Apply Redactions. Applying deletes the marked content and flattens the page. After that, run the select-and-search test above on the saved copy — verification takes seconds and is the whole point.

Without Acrobat, the reliable low-tech route is to remove the content in the source document, export a fresh PDF, and check the result. Printing a PDF to a new PDF does not reliably remove covered text either, so verify rather than assume.

Why Barecopy refuses to remove redaction marks

It could delete them. It deliberately doesn't. An unapplied redaction mark is a warning that sensitive text is still in the file — removing the mark would make the file look clean while the text stayed exactly where it was. That is a worse outcome than the problem it appears to solve.

So Barecopy reports the marks, tells you what they mean, and points at the editor command that applies them properly. Comments, attachments and earlier revisions it can remove safely, and does, on request.

Frequently asked

Can text under a black box really be recovered?

If the box was drawn on top, yes — by selecting and copying it, or by any tool that extracts text. Nothing sophisticated is needed.

Does flattening a PDF remove covered text?

Not dependably. Flattening merges annotations into the page; it does not guarantee that text under a shape is deleted. Use a real redaction and then verify by selecting and searching.

What about scanned documents?

A scan is an image, so there is no text layer to select — unless OCR has been run, in which case there is, and the same test applies. Covering part of an image with a box also leaves the original image data underneath.
